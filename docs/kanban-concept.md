# カンバン構想

方向性と実装状況の記録用。

## 全体像

カンバンは **プロジェクト配下** で使う。

```
グループ（任意）
└── プロジェクト（名前・アイコン画像・参加者）
    └── カンバン（ボード）
        └── リスト（列）
            └── カード（タスク・開始日/終了日）
                └── チェックリスト（枠）
                    └── チェックボックス（開始日/終了日）
```

## プロジェクト（実装済み）

- プロジェクト名を設定する
- アイコン画像を登録できる（`storage/app/public/project-icons`。未設定なら頭文字のアバター）
  - 選ぶと「画像表示エリアを変更」のポップアップが開き、ドラッグで位置、スライダー・ホイールで大きさを決める。枠の中だけを 512×512 の PNG に切り抜いて送る（`resources/js/image-cropper.js`、`x-image-cropper-dialog`）。プロフィールのアイコンも同じ（枠は丸）
- 設定画面で更新したあとは、そのまま設定画面に残る
- 参加者（メンバー）を設定する。役割は **オーナー / 参加者** の2種
  - オーナーだけがプロジェクトの編集・アーカイブ・参加者の変更をできる
  - 作成した人が自動でオーナーになる。オーナーが0人になる更新は弾く
- 作ると最初からリストが3つある: 開始前（青）/ 進行中（緑）/ 完了（赤）（`Project::createDefaultTaskLists`）
- **参加していない人は見られない**（一覧にも詳細にも出さない）
- **システム管理者も例外ではない**。秘匿性を優先し、参加していないプロジェクトは
  システム管理者にも見せない
  - `AppServiceProvider` の `Gate::before` は、対象が `Project` のときだけ素通りさせて
    `ProjectPolicy` に判断を任せている
  - 存在を悟られないよう、403 ではなく 404 を返す（`Response::denyAsNotFound()`）

## アーカイブ（実装済み）

プロジェクト・リスト・タスクは **まずアーカイブし、完全な削除はアーカイブ済みのものだけできる**。
（ユーザーとグループは今まで通り削除する）

- 3テーブルの `archived_at` で持つ（`App\Models\Concerns\Archivable`）
  - SoftDeletes にしないのは、アーカイブしたものを画面で見て元に戻すため
- プロジェクト
  - アーカイブ／復元はオーナーだけ。ダッシュボードから消え、ツールバーの「アーカイブ」に出る
  - 中身は読み取り専用になる（`ProjectPolicy::work` / `update` が拒否する）
  - 完全な削除もオーナーだけ（`ProjectPolicy::delete`）。ツールバーの「アーカイブ」から行う
  - 参加者・お気に入り・グループの割り当て・アイコン画像はそのまま残る
- リスト・タスク
  - アーカイブ／復元は参加者なら誰でも。プロジェクト内の「アーカイブ」タブから戻す
  - 元のリスト／ボードの末尾に戻る
  - リストをアーカイブしても中のタスクの `archived_at` は変えない。リストを戻せば一緒に戻る
  - タスクは Ctrl＋クリック（Mac は Cmd＋クリック）で複数選択でき、まとめて別のリストへ動かせる。ドラッグ中にボードの下へ出る枠に落とすと一括でアーカイブする（枠はリストに重ねず、出ている間はリストが縮む。重ねるとリストの末尾への移動と取り合ってちらつくため）
  - タスクの番号はアーカイブ済みとも重複させない。完全に削除すると、最大の番号に限り次のタスクで再利用される
  - 完全な削除も参加者なら誰でも。ただしプロジェクトがアーカイブ中のときは読み取り専用なので個別には消せない

## 左のプロジェクトリスト（実装済み）

プロジェクトの画面（ボード・編集）の左に、お気に入りと自分のグループごとのプロジェクトを出す
（`App\View\Components\Sidebar`）。他の画面はダッシュボードが同じ役割を持つので出さない。

- アーカイブ済みは出さない。参加していないプロジェクトも出さない
- 星の付け外しはその場で「お気に入り」に反映する（`$store.favorites` の初期値はここで入れる）
- ナビの開閉ボタンで開閉する。広い画面では畳める列、狭い画面では引き出し（外側を押すと閉じる）
- 畳んだ状態・グループの開閉は localStorage、スクロール位置は sessionStorage に覚える
  - 開いているプロジェクトが入っているグループは、畳んであっても開いて出す

## 期間（開始日・終了日）とガントチャート（未実装）

タスクに期間を持たせ、それをそのままガントチャートとして見られるようにしたい。

### 期間を持つもの

- **カード（タスク）** に開始日・終了日
- **カードの中のチェックボックス（チェックリストの項目）** にも開始日・終了日（データと入力は実装済み）
  - 「設計 2/1〜2/5」「実装 2/6〜2/20」のように、カードを分割せずに中で工程を刻める

どちらも **任意** にする。日付を入れていないものはガントに出さない（カンバンとしてだけ使える）。

### ガントチャート表示

- カンバンと同じデータを、時間軸で並べ替えて見せるだけの別ビューにする
  - 例: `/projects/{project}/gantt`
- 行の並びは リスト（列）→ カード → チェック項目 の入れ子
  - カードの行は、中のチェック項目の期間を包む帯として描く
- ガント上でバーをドラッグして期間を変えられると理想。まずは表示だけでもよい
- リアルタイム更新の対象に含める（カンバンでの変更がガントにも反映される）

### 未決事項

- 開始日だけ／終了日だけの入力を許すか
- カードの期間とチェック項目の期間がずれたときにどうするか
  （カード側を自動で広げる／警告を出す／何もしない）
- 稼働日（土日・祝日）を考慮するか
- 描画方法（自前の SVG / CSS グリッド か、ライブラリを入れるか）

## カレンダー（実装済み）

プロジェクトの「カレンダー」タブで、期間のあるタスクを月のカレンダーに帯で出す（`projects/partials/calendar.blade.php`、`resources/js/app.js` の `taskCalendar`）。

- 開始日〜終了日を帯にする。開始日だけ・終了日だけのものはその1日に出す。どちらもないものは出さない
- 出すのはタスクだけ（チェックリストの項目はガントチャートで扱う）
- 帯の色はリストの色。完了・中止は薄くして取り消し線。押すとタスクの詳細が開く（アーカイブ中のプロジェクトでは押せない）
- 週は日曜始まり。週の中で帯が重ならないよう段を分け、段の数だけ週の高さを伸ばす
- ボードの「フィルター」「マイタスク」がそのまま効く（締切日の絞り込みは終了日で判定）
- 見ている月はブラウザのタブを閉じるまで覚えておく。他の人の変更は `projects.board` の `calendar` で取り直す
- 見るだけ。帯のドラッグで日付を変える操作はまだない

## ファイル（実装済み）

プロジェクトの「ファイル」タブ（カレンダーの横）で、コメントに添付されたファイルを新しい順に一覧する（`projects/partials/files.blade.php`）。

- 画面の横幅いっぱいの表。ファイル名・タスク・投稿者・日時・大きさ・ダウンロード
- PDF はファイル名を押すとその場でプレビューする（`x-pdf-preview`。コメントの添付と同じ）。画像は小さく出す
- タスク名を押すと詳細が開く。アーカイブ中のタスクのファイルも出し、「アーカイブ中」と示す（開けない）
- ファイル名で絞り込める。他の人が添付したら `projects.board` の `files` で取り直す
- タブに件数は出さない

## リアルタイム更新（実装済み）

リスト・タスクの操作は、同じプロジェクトを開いている全員の画面へ反映する。

- Laravel Reverb（WebSocket）＋ Laravel Echo。compose の `reverb` サービスで動く
  - アプリからは `reverb:8080`、ブラウザからは `localhost:8081`（8080 は phpMyAdmin が使っている）
- チャンネルは `projects.{id}` のプライベートチャンネル。購読の可否は `ProjectChannel`
  （参加者だけ。システム管理者も例外ではない）
- `BoardChanged` は「変わった」という合図だけで、中身は送らない。受け取った画面が
  `/projects/{id}/board` からボードを取り直して差し替える（画面とサーバーの状態がずれない）
- ドラッグ・入力・複数選択の最中と自分の保存中は差し替えを待ち、手が空いたら反映する
- 並べ替えは `moved`（本人が動かしたタスク）だけ所属を変える。待っている間の古い画面から
  送られても、他の人の移動を巻き戻さないため
- プロジェクト自体の変更（名前・参加者・アーカイブ）は、画面ごと読み込み直す
- 通知に失敗しても保存は成功させる（Reverb が止まっていてもボードは使える）
- 接続が切れていた間の通知は届かないので、つなぎ直したら取り直す

## カードの開閉（実装済み）

タブの右の「拡張する / 折り畳む」で、全カードの詳細（説明・期間・チェックリスト・担当者）を出し入れする。
折り畳んだ状態が既定で、状態はブラウザに覚えておく（全プロジェクト共通）。

## ボードの絞り込み（実装済み）

タブの右の「フィルター」「マイタスク」で、ステータス・締切日（終了日）・ラベル・担当者で絞り込む。

- 画面の中でカードを隠すだけで、データは変えない（`$store.boardFilter`）。リストの件数は絞り込む前のまま
- 種類どうしは AND、同じ種類の中は OR。条件はブラウザのタブを閉じるまで覚えておく

## 操作の通知（実装済み）

操作の結果は、左下のトースト（`x-toast`、`session('toast')`）で知らせて5秒で消す。
`->with('status', 文言)` のメッセージも同じトーストで出す（画面の上に出す緑の帯はやめた）。
しゃぼん玉のように揺れながら浮かんで出てきて、消えるとき（閉じるボタンも）ははじけて小さな泡が散る。

- アーカイブとユーザーの削除は「キャンセル」で取り消せる。タスク・リストは元の位置に戻す
- 完全な削除とグループの削除は取り消せないので、キャンセルを出さない

## リストとタスクのメニュー（実装済み）

⋯ からメニューを開く。アーカイブ・編集はここから行う。
リストの編集はポップアップ（`projects/partials/list-edit-dialog.blade.php`）で行う。

- リスト: 新規タスクを追加 / 編集 / 複製 / アーカイブ
- タスク: 開く / 複製 / 移動 / アーカイブ
- タスクの移動は他のプロジェクトへもできる
  - 両方のプロジェクトで `work` できる人だけ。番号はプロジェクトごとの連番なので振り直す
- 複製は「○○ のコピー」をすぐ隣に置く。リストの複製はアーカイブ済みのタスクを含めない
  - タスクの担当者・チェックリストは一緒に写す。コメントは写さない

## タスクの詳細（実装済み）

カードを押すとポップアップで開く（`task-dialog` が入れ物、`task-detail` が中身）。
`data-task-form` の送信は画面遷移せず、サーバーが返した中身で差し替える。

- ステータス（`App\Enums\TaskStatus`）: 未着手 / 進行中 / 完了 / 中止 / 保留
- タイトル・説明・期間・担当者・チェックリスト・コメント
- 作成者と最終更新者を持ち、詳細画面の下に作成・最終更新の日時と一緒に出す（`created_by`, `updated_by`）
  - 最終更新（`updated_at` と `updated_by`）は `Task::recordActivity` で変える。フォローの通知になる動きと同じで、並べ替えとコメントでは変えない
- タイトルと説明は保存ボタンがなく、フォーカスを外すと保存する（Esc で取り消し。タイトルは Enter でも確定）
- 説明とコメントは書式を付けられる（Tiptap のエディタ。`resources/js/rich-text.js`）
  - 使える書式は文字の装飾だけ: 太字・斜体・下線・取り消し線・文字色・背景色・大きさ。ツールバーとショートカット（Ctrl+B など）で付ける
  - 色は8色、大きさは 小 / 標準 / 大 / 特大 から選ぶ。選択肢は `App\Support\RichText` の定数が正で、ツールバーもそこから作る
  - HTML で保存する。保存するときと表示するときに `RichText` が許可した書式だけで組み立て直す（それ以外のタグ・属性・値は捨てる）
  - 文字数の上限（10000）と空かどうかは、書式を外した文字で数える（`App\Rules\RichTextLength`）
  - カードの抜粋と通知の一覧には書式を外した文字を出す
  - 段落・リスト・リンク・画像などはまだ入れていない。足すときはエディタと `RichText` の両方に足す
- 期間は2か月並びのカレンダーで、最初の日と最後の日を順に押して選ぶ（開始日だけでも保存できる）
- チェックリストは1タスクに複数作れる。枠ごとに名前と進捗があり、中に項目を並べる
  - 枠も項目も取っ手のドラッグで並べ替えられる。項目は同じタスクの別の枠へも動かせる
  - 項目ごとに期間（開始日・終了日）と担当者（1人）を持てる。どちらも任意
    - 期間はタスクと同じカレンダー（`projects/partials/period-dialog.blade.php`）で選ぶ。開始日だけでもよい
    - 担当者はプロジェクトの参加者から選ぶ。同じ人をもう一度選ぶと外れる
    - 参加者から外れたり、参加していないプロジェクトへタスクを移すと、項目の担当からも外れる
    - タスクを複製すると項目の期間と担当者も写る
    - ボードのカードと「マイタスク」の絞り込みには、まだ項目の担当者を反映していない
- 担当者はプロジェクトの参加者だけ。参加者から外れたり、参加していないプロジェクトへ移すと担当から外れる
- ラベルは種類をプロジェクトごとに持ち（`labels`）、1つのタスクに5つまで付けられる
  - プロジェクトを作ると、優先度：高 / 中 / 低、メモ、確認中、保留中 が最初から入っている
  - 詳細画面のラベル欄から付け外し・追加・編集・削除ができ、種類の並びはドラッグで変えられる
  - カードには、折り畳んだときは色のバー、「拡張する」で色の丸と名前で出す。他のプロジェクトへ動かすと外れる
- コメントを編集・削除できるのは投稿した本人だけ（自分のコメントにだけ鉛筆の「編集」と赤い「削除」が出る）
  - 編集はその場の書式付きエディタで行う（Escape でやめる）。添付ファイルは変えられない
  - 編集で新しくメンションした人にだけ知らせる。前からメンションしていた人へは知らせ直さない
  - 直したコメントには「（編集済み 2026年11月10日 22:25）」のように最後に直した日時を出す（`updated_at` が投稿より後か。リアクションやメンションでは変わらない）
- コメントにはファイルを添付できる（`task_comment_attachments`）。クリップのボタンで選ぶか、コメント欄にドラッグ＆ドロップする
  - 1つのコメントに5つまで、1ファイル10MBまで（`TaskCommentAttachment::MAX_FILES` / `MAX_KILOBYTES`）。種類は問わない。ファイルだけなら本文はなくてよい
  - 秘匿性のため公開ディスクには置かない（`local` ディスクの `comment-attachments/{タスクの id}`）。`attachments.show` が参加者かを確かめてから渡す
  - PNG・JPEG・GIF・WebP はコメントの中に小さく出す。PDF は押すとその場のポップアップでプレビューする（`?download=1` でダウンロード）。それ以外（SVG・HTML も）は必ずダウンロードさせる（`nosniff`）
  - コメント・タスク・プロジェクトを消すと、ファイルの中身も消す
- コメントには絵文字でリアクションできる（`App\Enums\Reaction` の8種から選ぶ）
  - 1つのコメントに1人1つまで。同じ絵文字をもう一度押すと外れ、別の絵文字を押すと付け替わる
  - 絵文字ごとに件数を出し、自分が付けたものは色を変える。ホバーで付けた人の名前が出る
  - `emoji` の列は `utf8mb4_bin`（`utf8mb4_unicode_ci` だと絵文字どうしが同じ文字として比べられる）
- コメントは `@` で参加者をメンションできる。本文の「@名前」のうち参加者の名前だけをサーバーが記録する（`task_comment_mentions`）
  - エディタには「@名前」という文字のまま入れる。判定は書式を外した文字で行うので、名前の途中で書式が切り替わっていてもメンションになる（色付けはされない）
- メンションされると、ナビのベルに未読の件数が出る（`users.{id}` の合図 `NotificationReceived` でその場で増える）。押すと一覧が開く
  - タスクを開くと、そのタスクの自分宛ての通知（メンションもフォローも）が既読になり、見た分だけ件数が減る（一覧から開いても、ボードから開いても同じ）
  - 自分で自分をメンションしたものと、見られなくなったタスクのものは出さない
- リンクをコピーすると `?task=` 付きの URL になり、開くとそのタスクが開く
- 未実装: タスクのお気に入り、変更履歴
- タスクはフォローできる（`task_follows`）。詳細画面のリンクのコピーの横の目のボタンで付け外しする。自動ではフォローしない（作成者・担当者でも手動）
  - ボードのカードには、番号とステータスの下に目の印が出る。タブの右の「フォロー中」でフォローしたものだけに絞り込める（カレンダーにも効く）
  - フォローしたタスクに動きがあると、メンションと同じベルに通知が残る（`task_notifications`。種類は `App\Enums\TaskActivity`）
    - 通知する動き: コメント / ステータス / リストの移動（ドラッグ・メニュー。同じリストの中の並べ替えは除く）/ アーカイブ・戻す / 期間 / 担当者 / ラベル / タイトル / 説明 / チェックリスト（枠と項目の追加・変更・削除・チェック。並べ替えは除く）
    - 動かした本人には送らない。値が変わっていない保存では送らない。コメントでメンションした人には、メンションの通知だけを送る
    - コメント以外は、同じ人の同じ種類の動きが未読で残っていれば1件にまとめて新しくする（説明を何度も直しても1件）
    - 一覧ではメンションと混ぜて新しい順に出し、アバターの右下の印（@ / 目）で見分ける
    - アーカイブされたタスクの通知も出す。開くとその通知だけ既読にして、プロジェクトの「アーカイブ」タブへ案内する
  - 参加者から外れたり、参加していないプロジェクトへタスクを移すとフォローも外れる。複製ではフォローを写さない

## ボードの横スクロール（実装済み）

- プロジェクトの画面はページ全体をスクロールさせない。リストは画面の下まで伸ばし、タスクが多いときはリストの中でスクロールする
- 何もないところを掴んで横へドラッグするとスクロールする（`x-drag-scroll`。マウスのみ）
- カードやリストをドラッグしたまま端へ寄せると、ボードが横へ送られる（Sortable の AutoScroll）
- 掴んで動かしている間は、他の人の変更による差し替えを待つ

| `project_user` | プロジェクトと参加者の中間テーブル（`role`, `is_favorite`, `group_id`） | 実装済み |
| `task_lists` | リスト（列）。`name`, `color`（`#rrggbb`。プリセットは `ListColor`）, `position`, `archived_at` | 実装済み |
| `tasks` | タスク。`number`(プロジェクトごとの連番), `title`, `description`, `status`, `started_on`, `ended_on`, `created_by`, `updated_by`, `position`, `archived_at` | 実装済み |
| `task_user` | タスクの担当者 | 実装済み |
| `labels` | プロジェクトごとのラベルの種類。`name`, `color`, `position` | 実装済み |
| `label_task` | タスクに付けたラベル | 実装済み |
| `task_comments` | タスクのコメント | 実装済み |
| `task_comment_mentions` | コメントでメンションされた人 | 実装済み |
| `task_comment_attachments` | コメントの添付ファイル。`name`, `path`, `mime_type`, `size` | 実装済み |
| `task_comment_reactions` | コメントへのリアクション（1コメントに1人1つ）。`emoji` | 実装済み |
| `task_checklists` | タスクの中のチェックリスト（枠）。`title`, `position` | 実装済み |
| `task_checklist_items` | チェックリストの項目。並び順、完了フラグ、期間（`started_on`, `ended_on`）、担当者（`assignee_id`） | 実装済み |
| `task_follows` | タスクをフォローしている人 | 実装済み |
| `task_notifications` | フォローしたタスクの動きの通知（受け取る人ごと）。`actor_id`, `type`, `detail`, `read_at` | 実装済み |

`boards` テーブルは作っていない。**1プロジェクト＝1ボード**として、リストをプロジェクト直下に置いている。
複数ボードが必要になったら `projects` と `task_lists` の間に挟む。

※ シーダーはテーブルごとにファイルを分ける（`database/seeders/`）。
※ マイグレーションは1ファイル＝1テーブル。カラムを増減するときも追加のマイグレーションは作らず、そのテーブルの create を直して `migrate:fresh --seed` で作り直す。
