# カンバン構想

方向性と実装状況の記録用。

## 全体像

カンバンは **プロジェクト配下** で使う。

```
グループ（任意）
└── プロジェクト（名前・アイコン画像・参加者）
    └── カンバン（ボード）
        └── リスト（列）
            └── カード（タスク・開始日/終了日）
                └── チェックリスト（枠）
                    └── チェックボックス（開始日/終了日）
```

## プロジェクト（実装済み）

- プロジェクト名を設定する
- アイコン画像を登録できる（`storage/app/public/project-icons`。未設定なら頭文字のアバター）
- 参加者（メンバー）を設定する。役割は **オーナー / 参加者** の2種
  - オーナーだけがプロジェクトの編集・アーカイブ・参加者の変更をできる
  - 作成した人が自動でオーナーになる。オーナーが0人になる更新は弾く
- **参加していない人は見られない**（一覧にも詳細にも出さない）
- **システム管理者も例外ではない**。秘匿性を優先し、参加していないプロジェクトは
  システム管理者にも見せない
  - `AppServiceProvider` の `Gate::before` は、対象が `Project` のときだけ素通りさせて
    `ProjectPolicy` に判断を任せている
  - 存在を悟られないよう、403 ではなく 404 を返す（`Response::denyAsNotFound()`）

## アーカイブ（実装済み）

プロジェクト・リスト・タスクは **まずアーカイブし、完全な削除はアーカイブ済みのものだけできる**。
（ユーザーとグループは今まで通り削除する）

- 3テーブルの `archived_at` で持つ（`App\Models\Concerns\Archivable`）
  - SoftDeletes にしないのは、アーカイブしたものを画面で見て元に戻すため
- プロジェクト
  - アーカイブ／復元はオーナーだけ。ダッシュボードから消え、ツールバーの「アーカイブ」に出る
  - 中身は読み取り専用になる（`ProjectPolicy::work` / `update` が拒否する）
  - 完全な削除もオーナーだけ（`ProjectPolicy::delete`）。ツールバーの「アーカイブ」から行う
  - 参加者・お気に入り・グループの割り当て・アイコン画像はそのまま残る
- リスト・タスク
  - アーカイブ／復元は参加者なら誰でも。プロジェクト内の「アーカイブ」タブから戻す
  - 元のリスト／ボードの末尾に戻る
  - リストをアーカイブしても中のタスクの `archived_at` は変えない。リストを戻せば一緒に戻る
  - タスクは Ctrl＋クリック（Mac は Cmd＋クリック）で複数選択でき、まとめて別のリストへ動かせる。ドラッグ中に画面下へ出る枠に落とすと一括でアーカイブする
  - タスクの番号はアーカイブ済みとも重複させない。完全に削除すると、最大の番号に限り次のタスクで再利用される
  - 完全な削除も参加者なら誰でも。ただしプロジェクトがアーカイブ中のときは読み取り専用なので個別には消せない

## 左のプロジェクトリスト（実装済み）

プロジェクトの画面（ボード・編集）の左に、お気に入りと自分のグループごとのプロジェクトを出す
（`App\View\Components\Sidebar`）。他の画面はダッシュボードが同じ役割を持つので出さない。

- アーカイブ済みは出さない。参加していないプロジェクトも出さない
- 星の付け外しはその場で「お気に入り」に反映する（`$store.favorites` の初期値はここで入れる）
- ナビの開閉ボタンで開閉する。広い画面では畳める列、狭い画面では引き出し（外側を押すと閉じる）
- 畳んだ状態・グループの開閉は localStorage、スクロール位置は sessionStorage に覚える
  - 開いているプロジェクトが入っているグループは、畳んであっても開いて出す

## 期間（開始日・終了日）とガントチャート（未実装）

タスクに期間を持たせ、それをそのままガントチャートとして見られるようにしたい。

### 期間を持つもの

- **カード（タスク）** に開始日・終了日
- **カードの中のチェックボックス（チェックリストの項目）** にも開始日・終了日
  - 「設計 2/1〜2/5」「実装 2/6〜2/20」のように、カードを分割せずに中で工程を刻める

どちらも **任意** にする。日付を入れていないものはガントに出さない（カンバンとしてだけ使える）。

### ガントチャート表示

- カンバンと同じデータを、時間軸で並べ替えて見せるだけの別ビューにする
  - 例: `/projects/{project}/gantt`
- 行の並びは リスト（列）→ カード → チェック項目 の入れ子
  - カードの行は、中のチェック項目の期間を包む帯として描く
- ガント上でバーをドラッグして期間を変えられると理想。まずは表示だけでもよい
- リアルタイム更新の対象に含める（カンバンでの変更がガントにも反映される）

### 未決事項

- 開始日だけ／終了日だけの入力を許すか
- カードの期間とチェック項目の期間がずれたときにどうするか
  （カード側を自動で広げる／警告を出す／何もしない）
- 稼働日（土日・祝日）を考慮するか
- 描画方法（自前の SVG / CSS グリッド か、ライブラリを入れるか）

## リアルタイム更新（実装済み）

リスト・タスクの操作は、同じプロジェクトを開いている全員の画面へ反映する。

- Laravel Reverb（WebSocket）＋ Laravel Echo。compose の `reverb` サービスで動く
  - アプリからは `reverb:8080`、ブラウザからは `localhost:8081`（8080 は phpMyAdmin が使っている）
- チャンネルは `projects.{id}` のプライベートチャンネル。購読の可否は `ProjectChannel`
  （参加者だけ。システム管理者も例外ではない）
- `BoardChanged` は「変わった」という合図だけで、中身は送らない。受け取った画面が
  `/projects/{id}/board` からボードを取り直して差し替える（画面とサーバーの状態がずれない）
- ドラッグ・入力・複数選択の最中と自分の保存中は差し替えを待ち、手が空いたら反映する
- 並べ替えは `moved`（本人が動かしたタスク）だけ所属を変える。待っている間の古い画面から
  送られても、他の人の移動を巻き戻さないため
- プロジェクト自体の変更（名前・参加者・アーカイブ）は、画面ごと読み込み直す
- 通知に失敗しても保存は成功させる（Reverb が止まっていてもボードは使える）
- 接続が切れていた間の通知は届かないので、つなぎ直したら取り直す

## 操作の通知（実装済み）

アーカイブと削除は、左下のトースト（`x-toast`、`session('toast')`）で知らせて5秒で消す。

- アーカイブとユーザーの削除は「キャンセル」で取り消せる。タスク・リストは元の位置に戻す
- 完全な削除とグループの削除は取り消せないので、キャンセルを出さない

## リストとタスクのメニュー（実装済み）

⋯ からメニューを開く。アーカイブ・編集はここから行う。
リストの編集はポップアップ（`projects/partials/list-edit-dialog.blade.php`）で行う。

- リスト: 新規タスクを追加 / 編集 / 複製 / アーカイブ
- タスク: 開く / 複製 / 移動 / アーカイブ
- タスクの移動は他のプロジェクトへもできる
  - 両方のプロジェクトで `work` できる人だけ。番号はプロジェクトごとの連番なので振り直す
- 複製は「○○ のコピー」をすぐ隣に置く。リストの複製はアーカイブ済みのタスクを含めない
  - タスクの担当者・チェックリストは一緒に写す。コメントは写さない

## タスクの詳細（実装済み）

カードを押すとポップアップで開く（`task-dialog` が入れ物、`task-detail` が中身）。
`data-task-form` の送信は画面遷移せず、サーバーが返した中身で差し替える。

- ステータス（`App\Enums\TaskStatus`）: 未着手 / 進行中 / 完了 / 中止 / 保留
- タイトル・説明・期間（開始日だけ・終了日だけも可）・担当者・チェックリスト・コメント
- チェックリストは1タスクに複数作れる。枠ごとに名前と進捗があり、中に項目を並べる
  - 枠も項目も取っ手のドラッグで並べ替えられる。項目は同じタスクの別の枠へも動かせる
- 担当者はプロジェクトの参加者だけ。参加者から外れたり、参加していないプロジェクトへ移すと担当から外れる
- コメントを消せるのは投稿した本人だけ
- コメントは `@` で参加者をメンションできる。本文の「@名前」のうち参加者の名前だけをサーバーが記録する（`task_comment_mentions`）。通知はまだない
- リンクをコピーすると `?task=` 付きの URL になり、開くとそのタスクが開く
- 未実装: ラベル、タスクのお気に入り、メンションの通知、コメントの絵文字・添付、変更履歴

## ボードの横スクロール（実装済み）

- プロジェクトの画面はページ全体をスクロールさせない。リストは画面の下まで伸ばし、タスクが多いときはリストの中でスクロールする
- 何もないところを掴んで横へドラッグするとスクロールする（`x-drag-scroll`。マウスのみ）
- カードやリストをドラッグしたまま端へ寄せると、ボードが横へ送られる（Sortable の AutoScroll）
- 掴んで動かしている間は、他の人の変更による差し替えを待つ

## 想定するテーブル

| テーブル | 用途 | |
| --- | --- | --- |
| `project_groups` | プロジェクトをまとめる個人のグループ（`user_id`, `name`, `position`） | 実装済み |
| `projects` | プロジェクト（`name`, `icon_path`, `archived_at`） | 実装済み |
| `project_user` | プロジェクトと参加者の中間テーブル（`role`, `is_favorite`, `group_id`） | 実装済み |
| `task_lists` | リスト（列）。`name`, `color`（`#rrggbb`。プリセットは `ListColor`）, `position`, `archived_at` | 実装済み |
| `tasks` | タスク。`number`(プロジェクトごとの連番), `title`, `description`, `status`, `started_on`, `ended_on`, `created_by`, `position`, `archived_at` | 実装済み |
| `task_user` | タスクの担当者 | 実装済み |
| `task_comments` | タスクのコメント | 実装済み |
| `task_comment_mentions` | コメントでメンションされた人 | 実装済み |
| `task_checklists` | タスクの中のチェックリスト（枠）。`title`, `position` | 実装済み |
| `task_checklist_items` | チェックリストの項目。並び順、完了フラグ（期間の `started_on`, `ended_on` はガントと一緒に足す） | 実装済み |

`boards` テーブルは作っていない。**1プロジェクト＝1ボード**として、リストをプロジェクト直下に置いている。
複数ボードが必要になったら `projects` と `task_lists` の間に挟む。

※ シーダーはテーブルごとにファイルを分ける（`database/seeders/`）。
